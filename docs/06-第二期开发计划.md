### 1.1.1 分层健康度补充观察

- **parser 层**：四层调度（manual→structured→rule→generic）与三上限预算（maxCatalogPages/maxContentPages/maxTotalRequests）实现忠实于 01 §6；截断语义如实（isTruncated/truncatedByLimit 不静默）〔调研-P A2〕。两个结构性盲区：JS 拼接目录（层②仅支持 css chapterLinkSelector）与动态壳页（三层失败→DYNAMIC_PAGE_REQUIRED），均指向 A5。
- **data 层**：CatalogMerger 七步合并算法（03 §7.3）严格实现并有 10 个 MergeAlgorithm 单测锚定；进度/书签以 chapterId 关联、id 稳定即无损。缺口集中在"无 UI 的能力"（缓存统计/完整性校验/清理失效章）与迁移基建。
- **UI/reader 层**：八屏三态齐全；错误渲染全走 02 §10 映射表（QA 断错误类型不断文案的纪律可执行）；TextPager 引擎纯 JVM 可测（16 单测）。短板：位置恢复锚点粒度（分数均分假设）与自定义字体空白。
- **security 层**：57 用例覆盖 SSRF 全矩阵；生产装配无测试后门（allowListForTest 不传值）；DNS rebinding 在建连级拦截（DnsPinningResolver 生产默认生效）。二期风险面=新功能自带网络出口。
- **测试体系**：标准通道脚本（robocopy ASCII 副本规避中文路径 CNFE）已固化；资产缺口见 1.1 表格与第二部分测试基线行。

## 1.2 五份调研关键发现的交叉印证与矛盾点

**交叉印证（多份调研独立得出同一结论，可信度高）：**
1. **迁移基建是二期硬门禁**：WP-D §7/§8、WP-S §6、WP-Q §2.3(T-D4) 三方一致指出 AppContainer 未挂 addMigrations、无 MigrationTestHelper 先例、schemas 未挂 test assets——三方方案完全一致（build.gradle test assets 挂载 + Robolectric MigrationTest），互为印证。
2. **cacheChapters 无 UI 入口**：WP-D §1、WP-Q §1.2-7、05 整合日志均记载；【抽查】grep 全工程仅实现/契约/Worker 注释命中，无任何 UI 调用点。
3. **全工程无 ActivityResultContracts**：WP-U §3、WP-D §3/§5 双方 grep 互证——自定义字体、TXT/EPUB 导入、备份导出全部从 SAF 零起步。
4. **WebView 是否立项是二期最大分叉**：WP-P A5、WP-S §4-1、WP-Q T-P2/T-S2 三方一致以 security §6 六项前置为硬门禁（缺一票否决）。
5. **书签跳转丢位置**：WP-U §7 与 WP-Q §2.2(T-U4) 双方引用同一证据（ReaderScreen.kt:300-305）。

**矛盾点 / 口径差异（需要裁决或澄清）：**
1. **测试基线数字**：05 整合日志"阶段 8"记载 236（integration 28），WP-Q 实测 234（integration 26），且 `grep @Test`【抽查】=234 佐证 → **以 234 为准**（详见第七部分）。
2. **DB v2 时机**：WP-U §10-2 问"与二期其他变更合并还是独立先行"；WP-D §7 建议一次 v2 合并迁移；WP-S §9-5 建议"先建 MigrationTestHelper 基建再动 schema"。三者不矛盾但粒度不同 → 本计划裁定：**基建先行（M1），变更按"一次 v2 合并迁移"实现（M1 内），各变更拆独立 Migration 类**。
3. **书签跳转参数形态**：WP-U §10-3 给出 `?fraction=`（快）与 `?charOffset=`（依赖 #8，一步到位）两案；WP-Q T-U4 两者都测 → 建议直接 `?charOffset=`（避免二次契约回灌），见第九部分决策清单。
4. **批量缓存 UI 入口归属**：WP-D §1.5 说"data 侧先行，入口归 WP-U"；WP-U 调研未排期此项 → 本计划将其显式纳入 M3 批次，归属 WP-U。

# 第三部分 · 第二期功能优先级

分级口径：**用户价值 × 技术风险 × 依赖关系**；P0=缺陷修复+硬门禁+体验根基，P1=核心增量，P2=增强与长尾。

## P0（必做，二期成败线）

| 项 | 分级理由 |
|---|---|
| 1. 迁移测试基建 + DB v2 合并迁移（TD-1） | 一切 schema 变更的硬门禁；不做则 charOffset/sessions/文件化全被阻塞 |
| 2. DNS 语义细分（TD-7）+ RATE_LIMITED 映射 | 用户可见错误引导错误；契约 §4.1 增列小成本根治 |
| 3. 书签跨章跳转修复（TD-3）+ 独立书签页 | 书签是 MVP 已有功能的正确性缺陷，修复优先于新增 |
| 4. JS 分页静默缺章告警（TD-2） | 数据完整性问题；最低成本先告警，根治随 A5 决策 |
| 5. 批量缓存 WorkManager 化 + UI 入口（TD-5/D1） | 一期已承诺二期主项；数据面独立于 UI 可先行 |
| 6. RuleTester 在线测试（B2） | 规则系统闭环缺口；xpath 陷阱（TD-10）一并以校验期拦截兜底 |

## P1（核心增量）

| 项 | 分级理由 |
|---|---|
| 1. 自定义字体全链路（C3） | 用户呼声最高的阅读体验项；契约变更最大（§2.4+03 §4+DataStore），R5 度量一致性为专项风险，需整里程碑打磨 |
| 2. 字符偏移恢复锚点（C8） | 重排版后位置漂移的根治项；依赖 P0-1 迁移先行；与滚动精确化共用块→字符映射，实现联动顺 |
| 3. 滚动分数精确化（C2） | 长章进度失真可感知；引擎零改动纯 UI 侧换算口径替换，低风险高收益 |
| 4. 翻页动画视差/覆盖档（C1） | HorizontalPager 原生可承载，S~M 成本换来主流观感；卷曲档排除（见"不做"清单） |
| 5. TXT 本地导入（D3） | 本地书是阅读器高频刚需；去重键合成方案已可行（D13），M~L 级主功能 |
| 6. 真实站点样本夹具（B3/T-P1） | 234 用例全为合成 HTML 是最大测试盲区；同批复用 RuleTester 离线模式 |
| 7. 管线幂等 GET 重试退避（E2） | 弱网可用性核心；重试层放管线保预算不透明膨胀，全部 GET 无幂等顾虑 |
