## 3. DAO 关键查询（SQL 语义，方法名见实现）

### BookDao

```sql
-- observeShelf(): Flow<List<BookEntity>>
SELECT * FROM books WHERE isTemporary = 0
 ORDER BY (lastReadAt IS NULL), lastReadAt DESC, updatedAt DESC;

-- getBook(id) / findByNormalizedSourceUrl(url)
SELECT * FROM books WHERE id = :id;
SELECT * FROM books WHERE normalizedSourceUrl = :url LIMIT 1;

-- upsert（Room @Upsert）
INSERT OR REPLACE INTO books(...) VALUES(...);

-- 触达更新（阅读打开时）
UPDATE books SET currentChapterId = :chapterId, lastReadAt = :now, updatedAt = :now WHERE id = :bookId;

-- deleteBook(id)：依赖 FK CASCADE 级联 chapters/reading_progress/bookmarks
DELETE FROM books WHERE id = :id;

-- 临时书清单（继续阅读/历史用）
SELECT * FROM books WHERE isTemporary = 1 ORDER BY lastReadAt DESC LIMIT :limit;
```

### ChapterDao

```sql
-- observeChapterMetas：投影（绝不带 content 列）
SELECT id, bookId, chapterIndex, title, url, normalizedUrl, titleFingerprint,
       volumeTitle, isCached, isMissing, fetchedAt, wordCount
  FROM chapters WHERE bookId = :bookId ORDER BY chapterIndex ASC;

-- 目录合并取旧目录元数据
SELECT id, chapterIndex, title, url, normalizedUrl, titleFingerprint, isMissing
  FROM chapters WHERE bookId = :bookId ORDER BY chapterIndex ASC;

-- @Upsert 批量写目录（合并后的新/改章节）
-- saveContent
UPDATE chapters SET content = :json, contentHash = :hash, wordCount = :words,
       fetchedAt = :now, isCached = 1 WHERE id = :chapterId;

-- loadContent / getChapterByUrl
SELECT * FROM chapters WHERE id = :chapterId;
SELECT * FROM chapters WHERE bookId = :bookId AND normalizedUrl = :url LIMIT 1;

-- 指纹匹配（目录合并）
SELECT * FROM chapters WHERE bookId = :bookId AND titleFingerprint = :fp;

-- 缓存统计
SELECT COUNT(*) FROM chapters WHERE bookId = :bookId AND isCached = 1;
SELECT COUNT(*) FROM chapters WHERE bookId = :bookId;
SELECT IFNULL(SUM(LENGTH(content)), 0) FROM chapters WHERE bookId = :bookId AND isCached = 1;

-- isMissing 标记 / 删除正文（保留目录与进度）
UPDATE chapters SET isMissing = :missing WHERE id = :chapterId;
UPDATE chapters SET content = NULL, contentHash = NULL, wordCount = 0,
       isCached = 0, fetchedAt = NULL WHERE id = :chapterId;
```

### ReadingProgressDao

```sql
SELECT * FROM reading_progress WHERE bookId = :bookId;      -- suspend + Flow 两个版本
INSERT OR REPLACE INTO reading_progress(...) VALUES(...);    -- @Upsert
DELETE FROM reading_progress WHERE bookId = :bookId;
```

### BookmarkDao

```sql
SELECT * FROM bookmarks WHERE bookId = :bookId ORDER BY createdAt DESC;   -- Flow
INSERT INTO bookmarks(...) VALUES(...);   -- 返回 rowId
DELETE FROM bookmarks WHERE id = :id;
```

### SourceRuleDao

```sql
SELECT * FROM source_rules ORDER BY domain ASC;                      -- Flow + suspend
SELECT * FROM source_rules WHERE domain = :domain LIMIT 1;
SELECT * FROM source_rules WHERE domain = :domain AND enabled = 1 LIMIT 1;
INSERT OR REPLACE INTO source_rules(...) VALUES(...);                -- @Upsert
UPDATE source_rules SET enabled = :enabled, updatedAt = :now WHERE ruleId = :ruleId;
DELETE FROM source_rules WHERE ruleId = :ruleId;
```

## 6. 数据库版本与迁移策略

- 当前 `AppDatabase(version = 1)`，实体：books/chapters/reading_progress/bookmarks/source_rules。
- `room.schemaLocation = $projectDir/schemas`，schema JSON 随仓库提交（QA 迁移测试依据）。
- **迁移策略**：
  1. 任何 schema 变更 = 契约级变更，须经主 Agent 批准（架构师更新 03 后实施）。
  2. v1→vN 一律编写显式 `Migration`（ADD COLUMN / CREATE INDEX 优先，新增表用 CREATE TABLE）；**禁止** `fallbackToDestructiveMigration()` 出现在 release 构建；debug 构建允许，但必须打 WARN 日志。
  3. 迁移后必须跑 `MigrationTestHelper` 校验（WP-Q 用例）。
  4. 兼容策略：新增列一律可空或带默认值（老数据自然填充）；正文存储格式（§2.2 content JSON）字段升级走 `{"t":…,"v":…}` 结构加 `v2` 判别字段，读取端向前兼容。
- DataStore 同理：key 只增不删（§4）。

## 7. 目录更新匹配算法（URL 规范化 + 标题指纹）

目标：目录重新抓取后与旧目录合并，**保护阅读进度、书签、缓存与章节 id 稳定**；禁止盲目覆盖。

### 7.1 URL 规范化（UrlNormalizer，parser/util；入库前必须执行）

1. 解析为 URI；scheme 统一小写；host 统一小写。
2. 去默认端口（http:80 / https:443）；空 path 补 `/`。
3. 相对链接基于当前页 URL 解析为绝对 URL（Jsoup `absUrl`）。
4. 去除 fragment（`#…`）；去跟踪参数（`utm_*`、`from`、`spm`、`fr`、`share_*` 等，清单维护在实现内）。
5. 百分号编码统一解码后再按 UTF-8 重编码（大小写十六进制统一）。
6. 尾部 `/` 归一（path 为 `/` 以外时去掉一个尾 `/`）。
7. 保留 query（部分站点用 query 定位章节），但排除跟踪参数。

### 7.2 标题指纹（titleFingerprint）

```
fingerprint = sha256_hex( normalize(title) )   // 存前 32 hex 即可，冲突率可接受
normalize(title):
  1. 去首尾空白；连续空白折叠为单个空格
  2. 全角字符→半角（数字/字母/标点）
  3. 去掉常见装饰：书名号引号、章节标记词（"正文"、"VIP章节"、"最新章节"）的统一替换
  4. 统一小写（拉丁字母）
  5. 去除"第N章/第N节/Chapter N"中的编号空白差异（"第12章"与"第 12 章"一致）
```

> 指纹只用于**同书内**匹配，不跨书。

### 7.3 合并算法（ChapterRepository.replaceCatalog 内部执行）

```
输入：旧列表 O（按 chapterIndex 升序，含 id/normalizedUrl/fingerprint/isMissing），
      新目录 N（ParsedCatalog.chapters，站点真实顺序）

1. 反转检测：若 N 与 O 的 URL 序列完全互为倒序（或 ≥95% 章节序相反）→
   判定 detectedReversal=true，按反转后映射处理（章节 id 与规范顺序不变，
   仅目录展示排序交给 UI 的 CatalogSort）。
2. 构建 mapA = {normalizedUrl → 旧章}，mapB = {fingerprint → [旧章…]}。
3. 逐个处理 N[i]：
   a. normalizedUrl 命中 mapA → 同章：保留 id；标题变更则更新 title/fingerprint；unchanged++。
   b. 未命中 URL 但 fingerprint 命中 mapB（候选唯一，或用邻位提示消歧：
      旧章邻居 O[i-1]/O[i+1] 与新邻居匹配一致）→ 同章换址：
      保留 id，更新 url/normalizedUrl；updatedUrl++。
   c. 均未命中 → 新章节：分配新 id；added++。
4. 旧章节未出现在 N → isMissing=1（不删除，保护进度/书签/缓存）；markedMissing++。
5. 重新编号：chapterIndex 按 N 的站点真实顺序 0..n-1 重排（已匹配章节 id 不变）。
6. 匹配率 matchedRatio = (unchanged+updatedUrl) / max(|O|, |N|)；
   matchedRatio < 0.6 → requiresReview=true（UI 提示人工确认；仍写入，
   因 id 与进度已保护，回滚成本低）。
7. 输出 CatalogMergeReport；同步更新 books.totalChapters/latestChapterTitle/catalogUrl。
```

保证：任何步骤失败整批回滚（事务包裹）；进度/书签以 `chapterId` 关联，id 稳定即进度无损；新章节插入在当前章之前不影响已读位置。

## 8. 正文内容存储格式

```json
[
  { "t": "p",   "v": "段落文本…" },
  { "t": "img", "v": "https://…/pic.jpg", "alt": "插图" }
]
```

- 序列化：kotlinx-serialization（`ContentBlock` 多态，判别字段 `t`）。
- `contentHash`：对「全部 Paragraph 文本以 `\n` 连接」的 UTF-8 字节取 SHA-256，用于完整性校验（离线传输损坏检测）。
- `wordCount`：Paragraph 文本字符总数（不含图片）。

## 9. 存储限制与已知取舍

| 取舍 | 说明 | 二期出路 |
|---|---|---|
| 正文存 DB TEXT 列 | 一期按需缓存（当前±1 章），量级可控；避免文件管理复杂度 | 批量缓存量级大时迁 files 目录 + DB 存路径/状态（`content` 列保留兼容） |
| 封面不做本地文件缓存 | Coil 磁盘缓存已覆盖 | 二期可选归档 |
| 历史记录不独立建表 | 复用 books.lastReadAt | 二期阅读统计再建 reading_sessions 表 |
| isMissing 不删除 | 保护数据优先于存储整洁 | 提供"清理失效章节"入口 |
