# 方向 A · 多网站解析兼容性

## A1 · DOM 结构适配

**现状**：四层调度唯一入口 `pipeline/ParserPipelineImpl.kt`（三个 ParseStep）。层0 `manual/ManualRuleApplier.kt`（manual.* 字段 HIGH 优先）；层1 `structured/StructuredExtractorSuite.kt`（JSON-LD→OG→meta→内嵌 JSON 依序合并）；层2 `rule/RuleEngineImpl.kt`（extractDetail/Catalog/Content）；层3 `generic/GenericSmartExtractor.kt`（文本密度/段落数/链接密度，容器扫描 `a[href]` 提前止于 ≥30 命中）。目录锚点统一过滤 `util/CatalogAnchorFilter.kt:89-144`（同域+首段硬排除+书路径簇 60%+分卷锚+去重）。
**差距**（未覆盖形态）：① 章节列表由 JS 变量拼出（无 `<a>` 锚）——层②目录仅支持 css `chapterLinkSelector`（`rule/RuleEngineImpl.kt:303-311`，regex/jsonpath/xpath 均 Miss），层③只扫锚点；regex 选择器仅对详情字段有效（`rule/SelectorExecutor.kt:117` 对整页 HTML 求值）。② 目录正文混排页：目录侧靠聚类可部分抑制推荐列表污染，但"详情+目录同页"无专门识别，依赖通用层目录链接启发。③ 无限滚动/懒加载正文：静态 DOM 无内容 → `generic/pageLooksDynamic`（GenericSmartExtractor.kt:185-191）判动态壳 → `DYNAMIC_PAGE_REQUIRED`（CatalogParseStep/ContentParseStep/DetailParseStep 一致分支）。
**建议**：随 A5（WebView 渲染回 HTML）统一解决 ①③；② 可在 UrlClassifier.analyzePage（`core/UrlClassifierImpl.kt:159-191`）增加"目录链接+长正文共存"混合页标记，导入流对混合页自动二次解析其目录链接（复用现有 import 链路）。
**影响文件**：core/UrlClassifierImpl.kt、generic/GenericSmartExtractor.kt、presentation/importing/*。
**风险**：混合页二次解析多消耗请求预算；误判混合页导致重复导入。
**工作量**：S（A5 外的增量）。

## A2 · 目录分页 / 正文分页

**现状**：两套独立策略 `util/PaginationMerger.kt`（目录：已见页集合/URL 去重/重复率>60% 停/跨域守卫/跨页编号倒退→isLikelyReversed；正文：同 host+同目录前缀+标题归一一致+重复率+字符预算）。上限执行于 `pipeline/CatalogParseStep.kt:63-163`（maxCatalogPages=20、maxTotalRequests=30）与 `pipeline/ContentParseStep.kt:139-227`（maxContentPages 与规则 contentMaxPages 取小、maxContentChars=200k），触发即 isTruncated/truncatedByLimit 如实告知。下一页候选：规则 `CATALOG_NEXT_PAGE`/`nextPageSelector`（仅 css，CatalogParseStep.kt:206-212）→ 通用文本发现（GenericSmartExtractor.kt:161-182：下一页/下页/下一頁/next/›/»）。
**差距**：① JS 翻页站（linovelib 类静态目录正常，但部分站点"加载更多"按钮/JS 拼页）：静态无下一页锚 → 循环自然结束，**章节缺失但既不截断也不告警**（CatalogParseStep 无候选即视为完结，truncatedByLimit=false）——静默不完整是当前最危险的分页盲区。② 图标/无文本下一页按钮（text 为空即跳过，GenericSmartExtractor.kt:173）。③ 万章目录 20 页上限内塞不下时仅标记截断（合规但需 UI 明示）。
**建议**：① 最低成本缓解：目录页提取后若章节编号序列尾部明显跳号（如缺页码暗示）或页面含"加载更多/更多"按钮特征 → warnings 追加"疑似 JS 分页，目录可能不完整"，并把 A5 渲染作为根治方案；② 通用发现扩展 `rel=next` link 与 title/aria-label 属性兜底。
**影响文件**：generic/GenericSmartExtractor.kt、pipeline/CatalogParseStep.kt。
**风险**：启发式告警误报率（宁可多告警不可漏报）。
**工作量**：S（告警与 rel=next）；根治依赖 A5（L）。

## A3 · 编码

**现状**：`util/EncodingDetector.kt:38-84` 六级链：BOM（UTF-8/16LE/BE/32）→ 规则 encoding → Content-Type → meta charset（前 2KB）→ 字节探测（纯 ASCII/UTF-16 空字节模式/严格 UTF-8）→ GBK→GB18030 兜底；全部严格解码失败 → ENCODING_FAILED。
**差距**：① GBK 兜底"几乎总能解码成功"（字节覆盖宽），对 Big5/Shift_JIS/TIS-620 内容会产出无报错的乱码文本——缺少解码后质量校验。② 支持面：UTF-7 未探测（已废弃但历史上个别站使用）；规则/Schema 枚举仅 UTF-8/GBK/GB18030/BIG5（docs/03-数据模型.md:256），日韩站无法显式指定。③ meta 仅扫前 2KB（个别站 meta 声明靠后）。④ "带 BOM 的 GBK"实际不存在（GBK 无 BOM）；UTF-8 BOM+GBK 体因严格解码失败会正确落入下级，无缺陷。
**建议**：解码成功后增加轻量乱码校验（中文页 CJK 字符占比过低/替换符 U+FFFD 计数超阈值 → 该级结果视为失败继续下级，最终对 GBK 兜底结果同样校验）；UTF-7 风险大于收益建议不实现；Schema 编码枚举扩展与 B5 一并走契约回路。
**影响文件**：parser/util/EncodingDetector.kt、docs/03 §5、schemas/source-rule-v1.json。
**风险**：质量阈值需真实 GBK/Big5 样本回归（现有 9 个 EncodingDetectorTest 可扩充）。
**工作量**：S。

## A4 · 相对 / 协议相对链接

**现状**：`util/UrlNormalizer.kt` 七步归一（03 §7.1）：相对链接 `base.resolve()`（含 `../` 与 `//host/...` 协议相对，java.net.URI 按 RFC 3986 合并）；原始未编码中文路径经解码→UTF-8 重编码为大写十六进制（UrlNormalizerTest 已固化：`/book/剑.html`→`/book/%E5%89%91.html`）；仅 http/https；tracking 参数剥离；幂等。
**差距**：无实质盲区；仅 `lenientUri`（UrlNormalizer.kt:82-90）只对空格做 %20 重试，含引号/换行等非法字符的 href 仍返回 null → CatalogAnchorFilter 直接丢弃该锚（CatalogAnchorFilter.kt:105），无告警。
**建议**：lenientUri 失败时对该段整体按 UTF-8 百分号重编码再试一次；丢弃锚点计数入 warnings。
**影响文件**：parser/util/UrlNormalizer.kt、util/CatalogAnchorFilter.kt。
**风险**：低。
**工作量**：S。

## A5 · JavaScript 动态网页（二期重点）

**现状**：一期明确不做（01 §10）；三层失败且动态壳特征 → `DYNAMIC_PAGE_REQUIRED`（docs/02-接口契约.md:1202 映射"明确告知"）。数据获取**唯一漏斗**是 `pipeline/ParseContext.fetchPage`（ParseContext.kt:96-149）：SecureHttpClient.fetch → EncodingDetector → Jsoup.parse → PageData；UrlClassifierImpl.fetchAndAnalyze（core/UrlClassifierImpl.kt:127-156）有第二份同构实现（抓取+解码重复代码，二期重构点）。
**接入点设计（草案）**：
1. 在 parser 内部新增 `internal interface PageSource { suspend fun fetch(url, headers, ruleEncoding): AppResult<PageData> }`，现有 Http 实现抽自 ParseContext.fetchPage；`PageData`（document+DecodedPage）保持 parser 内部不变——**渲染结果只要"最终 HTML 字符串"，后续解码/清洗/抽取管线全部复用**。
2. domain 新增函数式接口 `RenderedPageFetcher { suspend fun renderHtml(url: String, timeoutMs: Long): AppResult<String> }`（纯 Kotlin 接口，实现由 di 装配层接 WebView 宿主）；ParseContext 构造注入可选实例（null=一期行为不变）。
3. 触发策略（两档）：a) 显式——规则 Schema 增 `renderMode: "webview"` 字段（03 §5 additionalProperties:false 需改 Schema）；b) 隐式——首层 Http 抓取经 pageLooksDynamic 判定动态壳且用户在导入页选择"尝试浏览器渲染重试"（不自动静默重试，避免流量/时限失控）。两种触发统一走 `fetchPage` 换源分支，满足"60s 任务预算/请求预算"照常计数。
4. 输出 HTML 重新走 EncodingDetector（可跳过，WebView 已是字符串）→ Jsoup.parse → 四层原样执行；净化一致性按 security §6-6 强制。
**安全边界**（强制引用 docs/security/审查报告-安全基线.md §6：74-83 六项前置，缺一不可）：独立 `:webview` 进程 + AIDL 白名单；禁文件/Content 访问；域名经 UrlSecurityValidator 且 shouldOverrideUrlLoading 逐跳 validateRedirect；addJavascriptInterface 仅最小接口（无 Context/File/反射，出入参类型+长度白名单）；CookieManager 隔离、不同步 Cookie 进请求头、禁第三方 Cookie 与敏感权限；采回 DOM 必须重过 ContentSanitizer。
**影响文件**：pipeline/ParseContext.kt、pipeline/ParserPipelineImpl.kt、core/UrlClassifierImpl.kt、domain/service|cache（新接口）、di/AppContainer.kt、security（WebView 宿主新文件）、docs/03 §5 + schemas/source-rule-v1.json（renderMode）、docs/02 §5（ParseOptions 或新增方法签名）、RuleEngineImpl.kt（renderMode 解析）。
**风险**：WebView 进程内存/稳定性；渲染与限流叠加超时；§6 任一前置未达标即不得启用（一票否决）。
**工作量**：L（含契约回路与 QA 用例）。

## A6 · 网站规则自动匹配

**现状**：`data/db/dao/SourceRuleDao.kt:21-22` `WHERE domain = :domain AND enabled = 1 LIMIT 1` **域名精确匹配**；`rule/RuleEngineImpl.loadRule`（RuleEngineImpl.kt:48-54）传入 `hostOf(url)` 全 host（www./m. 区分）；upsert 有"版本不降覆盖"保护（data/repository/SourceRuleRepositoryImpl.kt:54-74）。无泛域名、无路径规则。
**差距**：m./www. 子域各建一份规则；同一站不同路径不同结构无法表达；规则自动推荐/学习完全缺失。
**建议**：
- 匹配升级：DAO 改为按 host 取全量启用规则（规则量小，内存过滤），匹配顺序 = 完整 host > 去掉 www./m. 前缀的泛域 > 可选 `pathPrefix`（Schema 增可选字段，契约回路 02 §2.3/§5.3 + 03 §5）；优先级写死避免歧义。
- 规则自动学习/推荐（不接在线服务，**可行**）：当某域无规则且结构化/通用层成功（整体置信度 ≥MEDIUM 且章节数 ≥10）时，从通用层胜出元素反推 CSS 路径（新增 util 工具：沿父链 tag+id/class 去重生成稳定路径），合成 `auto.<domain>.v1` **disabled 草稿**入库（复用现有 upsert/启停），导入成功页提示"已生成建议规则，可在规则管理确认"。用户确认后变 enabled 即层②生效。全程本地、零网络、可关（设置开关）。
**影响文件**：data/db/dao/SourceRuleDao.kt、data/repository/SourceRuleRepositoryImpl.kt、parser/rule/RuleEngineImpl.kt、parser/generic（路径反推工具）、docs/03 §5、02 §2.3/§5.3、presentation/rules、ui/settings（开关）。
**风险**：反推选择器过度特异（id 随机站）→ 草稿永不启用无副作用；泛域匹配误命中他人规则 → 明确优先级+冲突告警。
**工作量**：匹配升级 M；学习推荐 M。

## A7 · 解析失败人工修正与辅助点选

**现状**：manual.* 全流程已闭环——新建/编辑（`presentation/rules/RuleManagerViewModel.kt`：SourceRuleDraft 12 选择器字段+清洗规则；本地 validateDraft:234-272 → RuleJsonValidator 权威校验 → upsert）；解析失败页有两个"编辑规则"入口（`ui/importing/ImportScreen.kt:185,227`）跳 `Routes.ruleEdit(domain)`（AppNavHost.kt:225，domain 预填）；错误映射表（docs/02-接口契约.md §10）"编辑规则兜底"全部落通。**缺**：无元素选取辅助，用户须手写 CSS；无试跑预览（依赖 B2）。

- 选项2：WebView 真渲染点选，体验最好，但依赖 A5 立项并满足 §6 全部前置（成本并入 A5）。
**影响文件**：ui/rules/RuleEditScreen.kt、presentation/rules/RuleManagerViewModel.kt、parser（RuleTester 复用 + CSS 路径生成工具）。
**风险**：选项1 树浏览器对大页面节点量需虚拟化/懒展开。
**工作量**：M（选项1）；选项2 随 A5。

# C · 待主 Agent 决策事项
