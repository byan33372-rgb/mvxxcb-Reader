## 1. 模拟翻页动画

- **现状**：`ui/reader/ReaderPageHost.kt` 用 HorizontalPager 默认平移滑动；三区点击经 `animateScrollToPage(page±1)`
  完成翻页，页边界点击回调 `onPrevChapter/onNextChapter` 切章（L77-90）。无任何自定义页变换（无 graphicsLayer/pageOffset 消费）。
- **差距**：与主流阅读器的"覆盖/视差/仿真卷曲"无差距级可比——一期明确从简，当前即"平移"档。
- **建议（成本分级）**：
  - 平移+视差（S）：HorizontalPager 原生支持，页内容 `Modifier.graphicsLayer { translationX = pageOffset * factor }`，
    由 `pagerState.currentPageOffsetFraction` 驱动，零架构改动。
  - 覆盖（S~M）：同上， nextPage 静止置底（zIndex 按 pageIndex），当前页平移覆盖其上；用 `graphicsLayer { zIndex }` +
    offset 组合即可，无需脱离 HorizontalPager。**结论：HorizontalPager 可承载自定义动画**（平移/视差/覆盖三档均可行）。
  - 仿真卷曲（L）：需将页内容栅格化为 Bitmap 后用 Canvas/RenderEffect 绘制卷曲网格（贝塞尔+阴影），逐帧随拖动更新；
    HorizontalPager 不适合承载（其页变换语义无法做"非平移"拖拽跟手），须改为自绘宿主或"拖动期自绘、松手期回退 Pager"混合方案。
    性能风险高（每帧位图合成），建议二期不做或列为可选实验项。
- **对三区点击与边界切章影响**：三区点击是每页 `pointerInput+detectTapGestures`（L107-120），与页变换正交，不受影响；
  覆盖/卷曲模式下首页向左/末页向右的边界手势仍走现有 onPrevChapter/onNextChapter 回调，无契约变更。
- **影响文件**：ReaderPageHost.kt（主要）、ReaderScreen.kt（如加动画档设置项）。
- **风险**：卷曲档与沉浸/亮度遮罩叠加时合成层级复杂；设置项 `pageTurnEffect` 若入 ReaderSettings = 契约 02 §2.4 变更 + DataStore 新 key。
- **工作量**：平移/视差 S；覆盖 S~M；卷曲 L（不建议二期必做）。

## 2. 上下滚动精度

- **现状**：`ui/reader/ReaderScrollHost.kt:94-108` `estimateScrollFraction` = 可见项均值高 × 总项数。
  缺陷三点：① 段落高度差异大（长短段混排）均值失真；② `Arrangement.spacedBy(paragraphSpacing)` 段距与尾部 Spacer 未计入
  分母，系统性低估总高；③ 尾部 key="tail_spacer" 项混入 totalItemsCount。恢复端 L44-56 按分数→页码→`scrollToItem(pages[page].blockStartIndex)`，
  即**恢复粒度实为"页首块"级，非行级**（文件头注记自认 MVP 精度）。双轨现状：scrollFraction（滚动实时）与 inChapterFraction（统一持久化）
  在 `ReaderViewModel.onScrolled/onPageChanged` 中同步写入同一值（ReaderViewModel.kt:167-196）。
- **差距**：实时分数误差可感知（长章尤甚）；恢复粒度页级可接受但实时进度条百分比随之失真。
- **建议**：用分页结果推导精确分数——TextPager 已产出每页 `PageSpan.startCharOffset/endCharOffsetExclusive`（契约 02 §9），
  滚动时以"首可见块所在页的 startCharOffset / 全章总字符"计算分数（块→字符映射可由 spans 线性扫描缓存），
  引擎零改动；恢复端仍 scrollToItem(blockStartIndex)，但恢复锚点精度随 §8 字符偏移升级自然提升到"页内任意点"。
  同时从 totalItemsCount 排除尾 Spacer（改用 key 过滤或单独计数）。
- **影响文件**：ReaderScrollHost.kt、ReaderViewModel.kt（onScrolled 口径注释）、TextPagerImplTest.kt（新增分数单调性用例）。
- **风险**：低。纯 UI 侧计算口径替换；注意分页结果为 null（未完成分页）时回退现估算。
- **工作量**：M。

## 3. 自定义字体（用户字体文件导入全链路）

- **现状**：全链路均为空白：① 无任何 SAF/ActivityResultContracts 使用（全工程 grep 无命中）；② 无 res/font 目录；
  ③ `TextPagerImpl.typefaceFor`（TextPagerImpl.kt:164-175）仅枚举 SYSTEM/SANS/SERIF/MONOSPACE 四种；
  ④ `ReaderFontFamily` 枚举注释自注"自定义字体文件 = 二期"（Models.kt:95）；⑤ DataStore 仅 reader.fontFamily 枚举 key（SettingsKeys.kt:21）；
  ⑥ Compose 侧 `composeFontFamily`（ReaderContentRender.kt:207-212）同样仅枚举映射。
- **差距**：二期需打通：SAF 选文件 → 存储副本 → 双侧加载 → 持久化。
- **建议方案（全链路）**：
  1. 入口：ReaderSettingsScreen（ui/settings/ReaderSettingsScreen.kt 字体区）加"导入字体"按钮，`ActivityResultContracts.OpenDocument`
     （type `font/*`+`application/octet-stream`，mime 兜底），复制到 `context.filesDir/fonts/<sha256>.ttf`（以内容哈希命名，
     天然去重与失效检测；复制而非 SAF 持久授权，避免授权丢失）。
  2. 模型：`ReaderSettings` 增 `customFontPath: String? = null`（或 `ReaderFontFamily` 增 `CUSTOM` 枚举 + 路径字段二选一，
     建议**枚举加 CUSTOM + 独立路径字段**，路径可空以便回退）；= 契约 02 §2.4 变更，须主 Agent 批准并回灌 03 §4。
  3. DataStore：`reader.fontFamily` 存 `CUSTOM` + 新增 key `reader.customFontPath`（SettingsKeys 规则"key 只增不删"，SettingsKeys.kt:13）。
  4. TextPager 侧：`ReaderTypography` 增可选 `typefacePath`（或直接注入 Typeface），`buildPaint`/`typefaceFor` 分支
     `Typeface.createFromFile(path)`；建议 ReaderViewModel 启动时加载一次 Typeface 并缓存，分页线程只读缓存。
  5. Compose 侧：`composeFontFamily` 对 CUSTOM 返回 `FontFamily(Font(typeface))`（compose ui-text 支持包装 android.graphics.Typeface）。
  6. **R5 度量一致性重估（重点）**：双侧必须使用**同一 Typeface 实例**（同一文件路径加载结果在 TextPaint 与 Compose 间一致；
     行高对齐机制不变：引擎强制行盒 = fontSize×multiplier，Compose lineHeight 同式）。layoutVersion 指纹（TextPagerImpl.kt:206-221）
     目前仅含 `fontFamily.name`，须追加字体文件内容 SHA-256（路径改名不影响指纹，内容变更才失效分页缓存）。
  7. 兜底：文件被清理/加载失败 → 回退 SYSTEM 并 WARN + 弱提示；ReaderSettingsScreen 展示已导入字体并可切回默认。
- **影响文件**：Models.kt、ReaderTypography（TextPager.kt 契约体）、TextPagerImpl.kt、ReaderContentRender.kt、
  ReaderSettingsDataStore.kt、SettingsKeys.kt、ReaderSettingsScreen.kt、ReaderViewModel.kt（buildSpec）、di 装配（可加 FontLoader）。
- **风险**：R5（双侧字体实例不一致 → 分页页码与绘制错位，页尾截字/空页）；字体文件损坏经 `Typeface.createFromFile` 抛异常须捕获；
  加粗仿真（fake bold）在部分非标字体下 TextPaint 与 Compose 渲染差异——建议自定义字体禁用 boldText 或 UI 提示。
- **工作量**：L（链路长 + 契约变更 + 单测：指纹含字体哈希、CUSTOM 回退、SAF 流程 androidTest 冒烟）。

## 4. 字号 / 行距 / 边距区间

- **现状**：`Models.kt:80-84` 默认与限值：字号 18（14..28）、行距 1.6（1.2..2.4）、段距 8（0..24）、边距 20（0..48）。
  独立设置页 Slider steps（ReaderSettingsScreen.kt:117-148）：字号 13 步（1sp/步）、行距 11 步（0.1/步）、段距 23 步、边距 47 步（1dp/步）；
  快捷面板字号 ±1（ReaderSettingsSheet.kt:87-93）。DataStore 层不做二次裁剪（ReaderSettingsDataStore.kt:28 注记），裁剪全在 UI。
- **差距**：中文字号主流阅读器普遍支持 12..40+；一行边界值对比市面偏窄。扩区间**无引擎风险**：TextPager 与 Compose 消费同一数值，
  仅重排版次数增多；DataStore 无裁剪，纯 UI 放宽即可。
- **建议**：字号 12..36（步进 1）、行距 1.0..2.4（步进 0.1）、边距 0..64；段距维持。UI 与 Models.kt 注释同步放宽；
  若加"预设档（小/标准/大）"可另立快捷按钮。
- **影响文件**：Models.kt（注释与默认不变）、ReaderSettingsScreen.kt、ReaderSettingsSheet.kt。
- **风险**：极小。字号 <12 在部分机型系统 fontScale 放大后可能过小，属体验问题非正确性问题。
- **工作量**：S。

## 5. 阅读手势

- **音量键翻页（S）**：现状全工程无任何 KeyEvent 处理（grep 仅命中无关的 volumeTitle 字段）。
  实现：ReaderScreen 根 Box `Modifier.onPreviewKeyEvent`（KeyEvent.KEYCODE_VOLUME_DOWN/UP → 下一页/上一页，返回 true 消费），
  仅 PAGE_SIMULATED 生效；需新设置开关（ReaderSettings 新字段 = 契约 02 §2.4 变更 + DataStore key）。
  风险：前台焦点须在阅读页（Screen 内组合层监听可行，无需改 Activity）；误触发无恢复（仅翻页）可接受。
- **长按选择文字 → 书签摘录（M~L）**：现状正文 Text 无 SelectionContainer（grep 无命中），`addBookmark(selectedText)` 通道已通
  （ReaderViewModel.kt:253-282；Bookmark.selectedText ≤200 字截断在 Repository 写入前，BookmarkEntity.kt:12 注记）。
  实现：滚动模式块外层包 `SelectionContainer`，翻页模式对整页 Column 包裹；选中经 `LocalTextToolbar`/selection 观察
  拿到选中文本后弹"加入书签"操作，调 `viewModel.addBookmark(selectedText)`。**冲突点**：SelectionContainer 长按与
  现有三区/整块点击（ReaderBlock clickable）并存时需把手势统一为 `detectTapGestures`（clickable 会让长按选择失效）；
  翻页模式页内文本是 PageSpan 截断片段，选中偏移仅页内有效，摘录拼接即可（不回写章内偏移，契约未要求）。
- **双击滚动/翻页（M）**：`detectTapGestures(onDoubleTap=…)` 可行；单双击歧义使工具栏点按延迟 ~300ms，
  建议双击仅绑定"滚动/翻页一屏"或干脆**不做**（与中央工具栏点按冲突收益低）——待决策。
- **边缘滑动调亮度（M）**：滚动模式左侧边缘竖向拖动（`pointerInput` + detectVerticalDragGestures，命中区 x<24dp）调亮度，
  跟手方案见 §6；翻页模式左缘横向拖动与 HorizontalPager 翻页冲突，**建议仅滚动模式启用或双模式统一"左缘竖向"**。
- **影响文件**：ReaderScreen.kt、ReaderScrollHost.kt、ReaderContentRender.kt（SelectionContainer）、ReaderSettings*。
- **风险**：手势叠加回归（三区点击/工具栏/翻页滑动是 MVP 核心交互，须 androidTest 冒烟回归）；
  选择文字与预取触发的滚动上报并存无冲突。
- **工作量**：音量键 S；摘录 M~L；双击 M；边缘亮度 M（可只做音量键+边缘亮度，合计 M）。

## 6. 亮度

- **现状**：ReaderScreen.kt:177-185 CUSTOM 黑遮罩（alpha=(1-brightness)×0.6 上限 0.6）；L218-233 CUSTOM 接管
  `window.screenBrightness`（0.01..1），onDispose 恢复 BRIGHTNESS_OVERRIDE_NONE；滑杆在 Sheet/设置页，
  变更即经 `updateSettings` → DataStore 全量写（ReaderSettingsDataStore.update 写全部 14 个 key）。
- **差距**：无手势跟随调节；且**拖动中每帧触发 DataStore 写盘**是潜在卡顿点（滑杆 onValueChange 直接 updateSettings）。
- **建议**：① 手势调亮度：拖动期用局部 `remember { mutableStateOf }` 直接驱动遮罩 alpha + window.screenBrightness（跟手、零持久化），
  `onDragEnd` 一次性提交 `updateSettings`（合一次写盘）；遮罩在内容之上工具栏之下层级不变。
  ② 顺带修复：Sheet/设置页滑杆改 onValueChangeFinished 提交，拖动中仅局部状态。
- **影响文件**：ReaderScreen.kt（手势区+遮罩）、ReaderSettingsSheet.kt、ReaderSettingsScreen.kt。
- **风险**：低。窗口亮度随拖动重建 DisposableEffect（key 含 brightness）会反复 dispose/apply——实现时应把 brightness 从
  DisposableEffect key 改为读 state，避免拖动期窗口属性抖动。
- **工作量**：M（含 DisposableEffect 重构）。

## 8. 更准的阅读位置恢复（字符偏移主锚点 + 分数兜底）

- **现状**：持久化锚点 = `reading_progress.inChapterFraction`（ReadingProgressEntity.kt:45，必填）+ scrollPosition/pageIndex 双模式字段；
  恢复链：`loadSavedFraction` → `pendingRestoreFraction` → 分页后 `applyPagination` 按分数映射页码/滚动块（ReaderViewModel.kt:470-487）。
  引擎侧 `PageSpan.startCharOffset/endCharOffsetExclusive`（契约 02 §9）已产出但**未持久化**；翻页模式恢复精度受
  `fractionToPage = floor(f*N)` 均分假设限制（ReaderPositionMapperImpl.kt:14-18）——分数按页均分线性映射，**页高不均时恢复偏差一页级**。
- **差距**：字体/字号/视口变化后，同一分数对应的页面内容漂移（前面的页占更多高度 → 恢复点相对内容后移/前移），长章且样式大改时偏差明显。
- **建议方案（字符偏移主锚点）**：
  1. **DB 迁移**：`reading_progress` 加列 `charOffset INTEGER NOT NULL DEFAULT -1`（-1 = 旧数据无锚点 sentinel），
     AppDatabase version 1→2，`data/db/migrations/Migration1To2.kt`（目录已建 .gitkeep 占位）；禁止 destructive 回退（AppDatabase.kt:22-23 注记），
     必须配 `MigrationTestHelper` 迁移测试（QA 挂钩 §11.5，app/schemas/2.json 随 KSP 导出）。
  2. **保存**：ReaderViewModel 保存进度时由分页结果反查当前页 `pages[currentPage].startCharOffset`（滚动模式取当前可见块所属页）写入。
  3. **恢复**：`pendingRestoreCharOffset ≥ 0` 时二分查找首个 `endCharOffsetExclusive > charOffset` 的 PageSpan → 页码（翻页）/
     `scrollToItem(blockStartIndex)`（滚动，可再按 charOffset 距页首字符比例加偏移）；charOffset<0（旧数据）回退现有 inChapterFraction 路径。
  4. **与翻页模式映射**：天然兼容——PageSpan 即页序号索引；分数兜底路径维持现状不动。
  5. **旧数据兼容**：首启读到 charOffset=-1 → 走 fraction 恢复 → 用户翻页后立即被新锚点覆盖，自愈无需数据修补。
  6. bookmarks 表同迁移可选加同名列（本项不做亦可，见待决策）。
- **影响文件**：ReadingProgressEntity.kt、ReadingProgressDao.kt、EntityMappers.kt、ReadingProgressRepositoryImpl.kt、
  ReadingProgress 模型（Models.kt:45-54）、ReaderViewModel.kt、AppDatabase.kt、新建 Migration1To2.kt、迁移测试、docs/03 §2.3 + 02 §8.6 回灌。
- **风险**：中。① 迁移为契约级变更（03 §6），须迁移测试兜底；② 章节内容更新（重抓）后 charOffset 与内容错位——
  分页基于当前内容重算，charOffset 越界时钳制到末页并在保存时校正，自愈；③ 与 §2 滚动精度改造联动实现更顺（同一套块→字符映射）。
- **工作量**：M。
