## 1. 威胁模型与总体结论

应用形态：单模块 Android 阅读器。攻击面集中在**用户粘贴/解析产物的 URL**（SSRF）、**站点返回的 HTML**（XSS/内容注入）与**网络边界资源滥用**（重定向循环、超大响应、高频请求）。一期无账号体系、无 WebView、无本地服务、无用户数据采集。

**总体结论**：一期安全目标（DoD 五点）全部达成。SSRF 校验基于解析后 IP 且覆盖 IPv4/IPv6 变体全家族；重定向逐跳复查；响应限额、限流、超时齐备；内容净化降维为受控块序列，结构性消灭 XSS 载体。残余风险均为低危且有明确缓解或二期计划（§7）。

## 2. 网络边界与 SSRF 防护

### 2.1 校验管线（UrlSecurityValidatorImpl）

1. **scheme 白名单**：仅 `http`/`https`，其余（ftp/file/javascript/data/ws 等）一律 `NON_HTTP_SCHEME`；缺失 scheme、opaque URI 报 `MALFORMED_URL`。
2. **主机提取不信任 JDK**：实测 JDK 对 `0x7f.0.0.1`、`127.1`、非 ASCII 主机返回 `getHost()==null`，且把 `0177.0.0.1` 当**十进制 177** 解析——因此本实现自行从 `rawAuthority` 提取主机、自行按 inet_aton 语义解析 IP 字面量变体（十进制整段 / 0x 十六进制 / 前导零按**八进制** / 1~4 段缩写）。
3. **DNS 解析级黑名单**：域名解析出**全部地址**，任一命中即拒绝（多 A 记录"一公一私"的 rebinding 形态同拦）。空解析结果视为失败（INVALID_HOST）。
4. **黑名单覆盖**（IPv4）：loopback 127/8；私网 10/8、172.16/12、192.168/16；链路本地 169.254/16（**云元数据 169.254.169.254 单列 METADATA_ENDPOINT**）；保留段 0/8、100.64/10（CGNAT）、192.0.0/24、192.0.2/24、198.51.100/24、203.0.113/24、198.18/15、224/4（组播）、240/4（含广播）。
   （IPv6）：::1、::、fc00::/7（ULA）、fe80::/10、fec0::/10、ff00::/8、2001:db8::/32；**内嵌 IPv4 还原判定**：::ffff: 映射形（含 `[::ffff:7f00:1]` 十六进制写法）、:: 兼容形、64:ff9b::/96（NAT64）、2002::/16（6to4）。
5. **防钓鱼混淆**：URL 携带 userinfo（`http://example.com@evil.com/`）一律 `INVALID_HOST`。
6. **重定向逐跳复查**：`validateRedirect` 对每一跳目标走同一管线（含 DNS 解析），重定向无法绕过私网黑名单。
7. **放行输出规范化 URL**：小写 scheme/host（IDN 转 punycode）、去默认端口、去 fragment、IPv6 保留方括号；后续连接均使用规范化结果。

### 2.2 纵深防御（DnsPinningResolver）

全应用唯一 OkHttpClient 的 `Dns` 挂钩指向 `DnsPinningResolver`：建连时解析结果再次过**同一黑名单**（[AddressGuard] 共享规则），全部命中则建连失败（DNS_FAILURE 语义）。由此封堵"校验时公网、建连时私网"的经典 DNS rebinding。

### 2.3 cleartext 流量取舍（主 Agent 裁定 1）

一期 Manifest `usesCleartextTraffic=true`：国内小说站大量纯 HTTP，禁用会导致大范围站点不可用。**接受的代价与既有缓解**：

- scheme 仍限 http/https（javascript:/data:/file: 等一律拦截）；
- 一期**无 WebView**、无本地 ServerSocket/Provider 暴露，应用内明文流量没有可被投毒的本地渲染面；
- 全部请求（含重定向每一跳）过同一校验管线，无旁路通道；
- TLS 侧不降级：未配置自定义 TrustManager/HostnameVerifier，OkHttp 默认策略（系统证书 + 主机名严格校验），`TLS_ERROR` 单列错误。

**二期要求**：若建立内置书源市场，应对 HTTPS 站点优先并逐步收紧 cleartext（按域名白名单放行 `networkSecurityConfig`）。

## 3. 传输与限额（SecureHttpClientImpl）

| 强制项 | 实现 |
|---|---|
| 唯一 OkHttpClient | 私有构造、无访问器；parser/data 无自建通道（契约 §4.2 红线） |
| 重定向 | `followRedirects=false` 手动逐跳；每跳 validateRedirect；上限 `maxRedirects=5`（TOO_MANY_REDIRECTS）；已访问 URL 集合检测循环（REDIRECT_LOOP）；跨主机跳转丢弃 Cookie/Authorization |
| 响应体上限 | Content-Length 预检 + 流式读取双重限额，超限立即中断连接报 RESPONSE_TOO_LARGE；`FetchRequest.maxBytes<=0` 回退默认 8MB |
| 超时 | connect 10s / read 15s（NetworkLimits）；`retryOnConnectionFailure=false` 防静默重试绕过限流 |
| 同主机限流 | host+port 维度记录上次请求时刻（注入 TimeProvider），间隔不足挂起等待；`delay` 可被协程取消打断 |
| 取消桥接 | 挂起等待：`suspendCancellableCoroutine` + `invokeOnCancellation{call.cancel()}`；正文读取（阻塞 IO，协程调度无法打断）：监视协程在外层取消瞬间对当前 Call 执行 `call.cancel()` 关闭底层连接 |
| 错误边界 | 业务失败一律 `AppResult.Failure(ReaderError)`；OkHttp 异常逐类映射 NetworkFailure（UnknownHost→DNS_FAILURE、Connect→CONNECTION_REFUSED、头前超时→CONNECT_TIMEOUT、体读超时→READ_TIMEOUT、SSL→TLS_ERROR、Canceled→CANCELLED）；无对应枚举的 IO 异常落 `ReaderError.Unknown`（01 §7 兜底桶）；**协程取消按控制流语义重抛 CancellationException**（结构化并发要求；NetworkFailure.CANCELLED 用于非取消上下文中的 call 中断） |
| 请求头 | Host/Content-Length/Connection/Transfer-Encoding 禁止调用方覆盖；UA/Referer/Cookie 由 parser 组装传入 |

**设计取舍**：`NetworkLimits.maxRequestsPerTask` 由 parser 管线按任务计数（ParseOptions.maxTotalRequests），客户端无任务边界概念，不做重复计数（契约 §5.2 已约定计数在 pipeline 侧）。

## 4. 内容净化（ContentSanitizerImpl）

策略为**降维而非黑名单清洗**：输出仅 `Paragraph(纯文本)` 与 `Image(url, alt)` 两种受控块，阅读器按块渲染，HTML 结构性不进入输出层。

- 危险元素整树剥离并计数：script/style/iframe/frame/frameset/object/embed/applet/link/meta/base/form 族/template/noscript/**svg/math**（后两者可携带脚本与外部引用）；
- 属性全丢弃：on* 事件、style、href 等不进入输出（链接仅保留锚文本）；
- 图片 src 白名单：http/https、data:image 前缀（"非图片 data:" 按裁定禁用）；含 scheme 但不在白名单（javascript: 等）丢弃该图并计入删除数；**无 scheme 相对地址原样保留不伪造**，绝对化由 parser 侧负责；
- 块级元素与 br/hr 为段落边界，行内元素透明合并文本，空白折叠（含 \u00A0/\u3000/\u200B）。

## 5. 可测试性与豁免边界（无后门声明）

- 唯一测试豁免点是构造参数 `allowListForTest`（Validator 与 DnsPinningResolver 同名参数，语义一致）：**默认空集**，只豁免"地址黑名单"一步，scheme/格式/凭据检查不豁免；生产装配不传该参数即无任何绕过开关（`di/AppContainer` 集成时不得传值）。
- `HostResolver` 函数接口仅替换"解析"动作，不影响黑名单判定；产品默认 `DefaultHostResolver`（系统 DNS）。
- SSRF 全矩阵单测（17 例）、MockWebServer 行为单测（21 例：重定向链/私网拦截/循环/超限/限额双路径/限流假时钟/超时/DNS/拒连/取消/脱敏）、净化单测（14 例）、DnsPinning 单测（5 例）**全部真实执行通过**。

## 6. WebView 二期启用前置强制要求（未满足前禁止启用）

一期代码不含任何 WebView。二期若引入（动态页渲染/内嵌浏览），以下全部为**启用前置条件**，缺一不可：

1. **独立进程隔离**：WebView 运行于独立进程（`:webview`），崩溃/漏洞不影响主进程数据；主进程与 WebView 进程仅通过受控接口（AIDL/Binder 白名单方法）通信。
2. **禁文件访问**：`allowFileAccess=false`、`allowFileAccessFromFileURLs=false`、`allowUniversalAccessFromFileURLs=false`、`allowContentAccess=false`。
3. **域名白名单**：仅加载经 UrlSecurityValidator 校验过的 http/https 域名；`shouldOverrideUrlLoading` 强制逐跳过 validateRedirect；禁 `setJavaScriptEnabled` 于非必要页面，启用时禁用 JS 与原生任意桥接。
4. **禁 JSI 泄漏**：`addJavascriptInterface` 只允许暴露最小接口对象（无 Context、无 File/Intent/反射能力的方法）；入参出参做类型与长度白名单校验。
5. **凭据隔离**：CookieManager 与主进程网络层隔离，禁止同步站点 Cookie 进应用请求头；禁用第三方 Cookie 与 geolocation/相机等权限授权。
6. **净化一致性**：WebView 采回的 DOM 必须重新过 ContentSanitizer 才能入库展示。

## 7. 隐私最小化清单

| 项 | 现状/要求 |
|---|---|
| 权限 | 仅 INTERNET + ACCESS_NETWORK_STATE（04 §1）；无定位/存储/通讯录等敏感权限 |
| 数据采集 | 无任何遥测/统计 SDK；无账号体系；请求不带设备指纹 |
| 日志脱敏 | 安全层所有错误/日志中的 URL 一律经 `redactQuery`：去查询串与 fragment、超 96 字符截断（01 §8 强制）；错误对象 `ReaderError.Network.url`/`ReaderError.Security.url` 同样脱敏，UI 不会展示完整带参 URL |
| 正文内容 | 日志禁止输出正文片段；净化层只输出受控块，无隐藏文本外带通道 |
| 本地数据 | 书/章节/进度均存本地 Room/DataStore；卸载即消失；不做云同步（一期范围） |
| Cookie | 不持久化站点 Cookie；跨主机重定向丢弃 Cookie/Authorization |

## 9. 残余风险登记

| # | 风险 | 等级 | 缓解/去向 |
|---|---|---|---|
| R-S1 | DNS rebinding 的"公网→另一公网 IP"窗口（校验与建连两次解析间） | 低 | 不构成 SSRF（两地址均过黑名单）；**阶段 6 终审更正：DnsPinningResolver 经 SecureHttpClientImpl 默认参数已在生产生效**，私网/保留段方向的 rebinding 已被建连级拦截，仅剩公网地址间切换残余 |
| R-S2 | Teredo（2001::/32）内嵌 IPv4（XOR 混淆）未还原判定 | 低 | 现网浏览器/系统基本不走 Teredo；真实公网地址仍过黑名单；已记录于实现注释 |
| R-S3 | cleartext http 明文可被中间人篡改页面内容 | 中 | 主 Agent 裁定接受（小说站现状）；缓解见 §2.3；二期按域名白名单收紧 |
| R-S4 | 通用 IOException（连接重置等）落 ReaderError.Unknown，§10 映射表无细分文案 | 低 | 用户得到通用网络异常提示；建议主 Agent 评估是否在 NetworkFailure 增列 GENERIC_IO（需契约变更回路） |
| R-S5 | "http://host:非数字端口/" 被 URI 解析为 registry 型 authority，端口被静默丢弃后按默认端口规范化 | 低 | 校验与实际连接的主机一致，无绕过；仅用户预期差异，已由测试固化行为 |
| R-S6 | 阻塞式正文读取依赖"关连接"打断；极端情况下（本机 socket 半关闭）取消延迟至 read 超时 | 低 | readTimeout 15s 兜底；协程取消最终必然生效 |
| R-S7 | `FetchRequest.maxBytes` 与 `NetworkLimits.maxResponseBytes` 双入口，调用方可单请求放宽 | 低 | 属契约设计（单请求限额本就允许覆盖默认）；parser 侧受 ParseOptions 约束，QA 回归覆盖 |
