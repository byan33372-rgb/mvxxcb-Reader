## 0 · 契约总则 `v1.0`

1. 包根：`com.mvxxcb.reader`。本文签名中的包路径即实现文件路径（`domain/model/Book.kt` = `app/src/main/java/com/mvxxcb/reader/domain/model/Book.kt`）。
2. 所有**接口/模型文件（纯签名）由 WP-M 按本契约一次性生成骨架**；各工作包只拥有对应实现与内部文件。这样并行开工第一天即可编译对齐。
3. 跨层错误以返回值传递（`AppResult`/`ParseOutcome`），禁止抛业务异常跨层；实现内部异常必须在层边界捕获转换。
4. 挂起约定：网络/DB/解析方法一律 `suspend`；UI 观察数据一律 `Flow`/`StateFlow`。
5. 依赖红线：presentation 不得 import `parser.*`、`data.*`、`security.*`、`org.jsoup.*`、`okhttp3.*`、`androidx.room.*`；data 不得 import `parser.*`、`org.jsoup.*`；parser 不得 import `androidx.room.*`、Compose。
6. ViewModel 创建约定（手动 DI）：每个 ViewModel 提供 `companion object { fun factory(container: AppContainer, …): ViewModelProvider.Factory }`。
7. 所有时间戳一律 `Long`（epoch 毫秒，UTC），由注入的 `TimeProvider` 产生。

```kotlin
package com.mvxxcb.reader.common.result

sealed interface AppResult<out T> {
    data class Success<out T>(val value: T) : AppResult<T>
    data class Failure(val error: com.mvxxcb.reader.domain.error.ReaderError) : AppResult<Nothing>

    fun getOrNull(): T? = (this as? Success)?.value
    fun errorOrNull(): ReaderError? = (this as? Failure)?.error
    fun <R> map(transform: (T) -> R): AppResult<R> =
        when (this) { is Success -> Success(transform(value)); is Failure -> this }
    fun onSuccess(block: (T) -> Unit): AppResult<T> { if (this is Success) block(value); return this }
    fun onFailure(block: (ReaderError) -> Unit): AppResult<T> { if (this is Failure) block(error); return this }
}
```

```kotlin
package com.mvxxcb.reader.security

interface UrlSecurityValidator {
    /** 首次请求前校验：scheme 仅 http/https；拒绝 localhost/回环/私网/链路本地/保留段/云元数据地址 */
    fun validate(rawUrl: String): UrlCheckResult

    data class Allowed(val normalizedUrl: String) : UrlCheckResult
    data class Blocked(val reason: BlockedReason, val detail: String) : UrlCheckResult

enum class BlockedReason {
    NON_HTTP_SCHEME, INVALID_HOST, MALFORMED_URL,

}
```

> 校验必须基于**解析后的 IP**（含 DNS 解析结果与每次重定向后的主机），不能只看字符串；实现需防御十进制/十六进制 IP 变体与 IPv6 回环/ULA。

### 5.3 站点规则引擎

```kotlin
package com.mvxxcb.reader.parser.rule

/** parser 内部使用的已解析规则（不进 domain） */
data class ParsedSiteRule(
    val ruleId: String,
    val domain: String,
    val isManual: Boolean,              // ruleId 前缀 "manual." 即人工规则
    val encoding: String?,
    val selectors: Map<RuleSelectorKey, SelectorSpec>,
    val cleaningRules: List<CleaningRule>,
    val contentMaxPages: Int?,
)

enum class RuleSelectorKey {
    BOOK_NAME, AUTHOR, COVER, DESCRIPTION,
    CATALOG, CATALOG_NEXT_PAGE, CHAPTER_TITLE, CHAPTER_LINK,
    CONTENT, CONTENT_NEXT_PAGE, NEXT_CHAPTER, PREVIOUS_CHAPTER,
}

sealed interface SelectorSpec {
    data class Css(val expr: String, val attr: String = "text") : SelectorSpec      // attr: text|html|href|src|abs:href…
    data class Xpath(val expr: String) : SelectorSpec
    data class Regex(val expr: String, val group: Int = 1) : SelectorSpec
    data class JsonPath(val expr: String) : SelectorSpec
    // 复杂度上限：xpath 深度≤10、regex 长度≤200、jsonpath 深度≤8（实现校验，超限报 INVALID_ARGUMENT）
}

data class CleaningRule(val type: CleaningType, val pattern: String, val replacement: String = "")
enum class CleaningType { REGEX, SELECTOR, WHITESPACE }
```

## 13 · v1.0.3 增补记录（主 Agent 批准，2026-11-09，集成期实现确认）`v1.0.3`

以下为六个工作包实现后经主 Agent 批准的偏差回灌与语义澄清；正文签名以本节为准修订。

### 13.1 构造签名确认（装配依据，AppContainer v1 已按此接线）
1. `ParserPipelineImpl(secureHttpClient, ruleEngine, sourceRuleRepository, contentSanitizer, dispatchers, timeProvider, logger)` —— 7 参（timeProvider 预留解析任务超时预算）。
2. `RuleEngineImpl(sourceRuleRepository, contentSanitizer)` —— 双参；正文块统一经 ContentSanitizer 构建，空输出由 TextCleaner 兜底。
3. `UrlClassifierImpl(secureHttpClient, ruleEngine, dispatchers, logger)`。
4. `SecureHttpClientImpl(validator, limits = NetworkLimits.DEFAULT, timeProvider, dispatchers, logger?)` —— 协程取消重抛 `CancellationException`（结构化并发语义；`NetworkFailure.CANCELLED` 用于非取消上下文的 call 中断）。
5. `UrlSecurityValidatorImpl(hostResolver = DefaultHostResolver(), allowListForTest = emptySet())` —— 生产装配不传 allowListForTest（无测试后门）。
6. `ContentCacheManagerImpl(chapterRepository, chapterDao, fetcher, dispatchers, logger)`。

### 13.2 语义澄清
1. **编码探测链**：BOM → **规则 encoding**（用户显式配置优先于声明错误的响应头）→ Content-Type → meta charset → 字节探测 → GBK/GB18030 兜底。
2. **ReaderContent.title**：使用目录章节标题（chapter.title）；解析页标题仅用于目录条目落库。
3. **loadChapterByUrl**：URL 未命中目录条目 → 返回 `State.CHAPTER_NOT_FOUND`，**不自动补录**（§6.2 原文"同步补目录条目"语义废止；补录由 §13.3 appendChapter 显式完成）。
4. **loadChapter**：不前置校验书存在；章节存在即取数（书行由 FK 保证）。成功后对 book 做尽力而为触达更新（currentChapterId/lastReadAt/updatedAt，失败忽略）。
5. **截断语义**：正文分页达上限 → `ParsedChapterContent.isTruncated=true`；目录分页达上限 → `ParsedCatalog.truncatedByLimit=true`（不静默截断）。
6. **TempRead 持久化**：章节页导入/临时阅读必须持久化单章目录条目与正文（参考实现缺口补齐），保证临时书可直接阅读。
7. **目录合并语义细化（WP-D 实现决定，主 Agent 追认）**：缺失章索引挪至目录尾部区段 `n..n+k`；首建目录（旧目录为空）matchedRatio=1.0；空新目录拒绝写入并返回 `Parse(CATALOG_EMPTY)`；事务内整批回滚。
