## 1. 输入与共识

- 产品定位：Android 原生网页小说阅读器。核心闭环：粘贴网址 → 解析（详情/目录/正文）→ 统一数据 → 沉浸阅读 → 进度记忆 → 离线缓存。
- 环境事实：项目从零搭建；本机暂无 JDK/Gradle/Android SDK，本方案给出的版本号为**知识库稳定版本，未验证网络下载**，构建机就绪后必须按第 12 节清单实机验证。
- 技术栈既定：Kotlin + Jetpack Compose + Material 3 + MVVM + Repository + Coroutines/StateFlow + Room + DataStore + OkHttp + Jsoup + kotlinx-serialization + WorkManager + Navigation Compose。
- 主 Agent 既定决策（本方案遵守，不推翻）：单 Gradle 模块 `:app`；applicationId `com.mvxxcb.reader`；轻量手动 DI（不上 Hilt）；解析层只出领域模型+置信度；所有 HTTP 走 security 层 SecureHttpClient；目录更新按 URL 规范化+指纹匹配禁止盲目覆盖。

## 2. 总体分层架构（文字版）

```
┌─────────────────────────────────────────────────────────────────────┐
│  ui 层（Compose Screen / 主题 / 组件）                                │
│  ui/{shelf,import,bookdetail,catalog,reader,settings,rules}          │
│  ui/theme · ui/components            只渲染 State，不发业务请求        │
└───────────────▲─────────────────────────────────────────────────────┘
                │ StateFlow / 事件回调
┌───────────────┴─────────────────────────────────────────────────────┐
│  presentation 层（ViewModel + UiState + 单次事件）                    │
│  presentation/{navigation,shelf,import,bookdetail,catalog,reader,    │
│                settings,rules}                                       │
│  只依赖 domain 接口；不含 Jsoup/OkHttp/Room 任何符号                   │
└───────────────▲─────────────────────────────────────────────────────┘
                │ domain 接口（Repository / Service / Validator）
┌───────────────┴─────────────────────────────────────────────────────┐
│  domain 层（纯 Kotlin：模型 + 错误体系 + 全部接口声明）                │
│  domain/{model,error,repository,rule,service,cache}                  │
└───▲───────────────▲───────────────────▲─────────────────────────────┘
    │               │                   │
┌───┴────────┐ ┌────┴─────────────┐ ┌───┴──────────────────────────┐
│ data 层    │ │ parser 层        │ │ security 层                  │
│ Room/DAO   │ │ UrlClassifier    │ │ UrlSecurityValidator(SSRF)   │
│ DataStore  │ │ 四层解析管线      │ │ SecureHttpClient(限流/限大小) │
│ Repository │ │ 站点规则引擎      │ │ ContentSanitizer(净化)       │
│ CacheImpl  │ │ 编码/分页合并     │ │                              │
└───▲────────┘ └────▲─────────────┘ └───▲──────────────────────────┘
    │               │                   │
    │      parser ──调用──▶ security.SecureHttpClient 接口
    │      data(cache) ──调用──▶ domain.ChapterFetcher（由装配层接 parser）
    └──────────── di 装配层（AppContainer，主 Agent 所有）────────────┘
```

**依赖规则（强制）**

1. 依赖方向只允许 `ui → presentation → domain ← {data, parser, security}`，装配层（di）可见全部实现。
2. `domain` 是纯 Kotlin（无 Android/Compose/OkHttp/Jsoup 符号），保证单测可跑 JVM。
3. parser 只能通过 `SecureHttpClient` 接口发网络请求；data 只能通过 `ChapterFetcher`（domain 函数式接口）间接使用 parser——**禁止 data 直接 import parser 包**。
4. `Jsoup Document`、OkHttp `Response`、Room `Entity` 不得出现在各自层之外（Entity↔领域模型在 `data/mapper` 转换）。
5. 解析器对外只返回统一领域模型 + 解析置信度（`ParseOutcome`），低置信度不得当可靠结果。
6. 错误以返回值传递（`AppResult` / `ParseOutcome`），跨层不抛业务异常。

## 5. 线程与异步规则（强制）

1. **调度器分配**：网络与文件 IO → `Dispatchers.IO`；JSON 编解码、正文清洗、规则匹配、分页计算 → `Dispatchers.Default`；UI/Compose → `Main`。全部经 `DispatcherProvider` 注入，**禁止直接引用全局 Dispatchers**（便于 QA 注入虚拟调度器）。
2. **ViewModel**：对外只暴露 `StateFlow<UiState>`（`stateIn(viewModelScope, WhileSubscribed(5_000))`）与必要的一次性事件 `SharedFlow`；禁止把 `Flow` 直接透传给 Compose 后自行 collect 业务逻辑。
3. **Room**：列表用 DAO 返回的 `Flow`（Room 自主切线程）；单次写用 `suspend`。禁止在 `Main` 上调阻塞 DAO。
4. **取消协作**：解析管线在每次分页/分页请求循环迭代间检查 `isActive`；OkHttp 调用必须响应协程取消（实现用 `suspendCancellableCoroutine` 桥接并 `call.cancel()`）。
5. **超时预算**：单请求超时见 security 限额（连接 10s/读 15s）；单次解析任务总预算 60s；导入全流程（详情+目录）预算 120s；正文分页合并单章预算 30s。超时转化为对应 `ReaderError`，不允许无限等待。
6. **进度保存**：阅读中滚动/翻页进度**防抖 500ms** 合并写入；`ON_STOP` 立即强制保存一次；写进度不阻塞阅读（fire-and-forget + 失败重试一次）。
7. **预取**：临近章尾（滚动 >80% 或翻页至倒数第 2 页）触发下一章预取，预取失败静默（只记日志），不得打扰当前阅读。
8. 串行原则：同一本书的章节抓取请求串行（防限流）；不同书互不影响。

## 6. 解析四层策略调度设计

四层：①标准结构化（JSON-LD → Open Graph → meta → 内嵌 JSON）②域名站点规则 ③通用 HTML 智能提取（文本密度/段落数/内容长度）④人工修正规则（用户手动指定选择器）。

**执行顺序与合并策略（契约级，详见 02 §5）**

```
输入：目标 URL + 页面 HTML（经 SecureHttpClient 抓取、EncodingDetector 解码）
步骤 0  若该域名存在「人工规则」（SourceRule，用户显式配置）：
        先应用人工规则已配置的字段（用户意图最高优先），其余字段继续走自动层。
步骤 1  层① 结构化提取 → 记录每字段置信度。
步骤 2  层② 站点规则（RuleEngine 按域名取启用规则）→ 仅填充 ① 未填或置信度为 LOW 的字段；
        同字段冲突时，取置信度更高一方；同级取先到（①）。
步骤 3  层③ 通用智能提取 → 同合并规则填充剩余字段。
步骤 4  汇总：整体置信度 = 关键字段（书名/目录/正文）置信度取 min；
        若整体 < ParseOptions.confidenceThreshold → 判定 LOW，结果不得当可靠数据，
        UI 必须展示「低置信度」警示并提供人工修正入口；解析失败场景给出明确原因。
锁定规则：字段一旦被某层以 HIGH 置信度填充，后续层不得覆盖。
```

- **逐层失败不中断**：某层抛错只记入 `LayerTrace`，继续下一层；全部失败才返回 `ParseOutcome.Failure`（携带完整 trace 与错误详情）。
- **人工修正兜底（层④第二种形态）**：当 ①②③ 整体失败或低置信度时，导入流进入「人工修正」分支：用户按元素类型填写选择器 → 生成草稿规则（`ruleId = manual.<domain>`）→ 保存即层④规则，此后该域自动走步骤 0。**禁止用假数据填充解析失败字段**，允许字段为空。
- **两种分页严格区分**（`PaginationMerger` 内部两个独立策略）：
  - 目录分页：沿 `catalogNextPageSelector`/智能发现下一页链接抓取合并；上限 `maxCatalogPages`（默认 20）页。
  - 正文分页：沿 `nextPageSelector` 合并同章多页；**合并防漏页/重复/倒序/误入下一章**校验：页 URL 前缀一致性、标题一致性、下一页 URL 去重集合、内容增量校验（新页与已有内容重复率 > 60% 判重复终止）；上限 `maxContentPages`（默认 10）页、`maxContentChars`（默认 200,000 字符）、`maxTotalRequests`（默认 30 次）。
  - 任一上限触发 → 置 `isTruncated/truncatedByLimit=true`，如实告知用户，不静默截断。

## 7. 错误模型与异常体系总览

原则：**错误是数据不是异常**。业务错误以 `AppResult.Failure(ReaderError)` / `ParseOutcome.Failure` 返回；实现内部可抛异常，但必须在层边界捕获转换。崩溃级异常（OOM 等）不在此模型内。

```
ReaderError (sealed interface, 完整定义见 02 §3)
├── Network(failure: NetworkFailure, url, statusCode, cause)
│     NetworkFailure: INVALID_URL / DNS_FAILURE / CONNECT_TIMEOUT / READ_TIMEOUT /
│       CONNECTION_REFUSED / TLS_ERROR / HTTP_ERROR_STATUS / TOO_MANY_REDIRECTS /
│       REDIRECT_LOOP / RESPONSE_TOO_LARGE / RATE_LIMITED / EMPTY_RESPONSE /
│       CANCELLED / OFFLINE
├── Parse(failure: ParseFailure, layer?, fieldErrors: Map<String,String>, detail, cause)
│     ParseFailure: UNSUPPORTED_STRUCTURE / DETAIL_INCOMPLETE / CATALOG_EMPTY /
│       CATALOG_PAGINATION_FAILED / CONTENT_EMPTY / CONTENT_PAGINATION_FAILED /
│       PAGINATION_LOOP_DETECTED / ENCODING_FAILED / DYNAMIC_PAGE_REQUIRED /
│       LOW_CONFIDENCE / DUPLICATE_CHAPTER_CONFLICT / TIMEOUT_BUDGET_EXCEEDED
├── Security(reason: BlockedReason, url, detail)      # SSRF/scheme/限额拦截
├── Storage(failure: StorageFailure, detail, cause)   # DB_ERROR / DISK_IO / DISK_FULL / CACHE_CORRUPT
├── State(failure: StateFailure, detail)              # BOOK_NOT_FOUND / CHAPTER_NOT_FOUND /
│                                                     # CHAPTER_NOT_CACHED / INVALID_ARGUMENT
└── Unknown(detail, cause)
```

- 每个错误可映射为用户文案 key + 恢复动作（映射表为契约一部分，见 02 §10），UI 一律经映射表展示，禁止各屏自造错误文案。
- 解析结果永远携带 `LayerTrace`（尝试了哪些层、各层结果），供调试与「失败原因」展示。
- QA 断言错误类型而非文案字符串。

## 8. 横切设计

- **DI（手动）**：`AppContainer(context)` 持有单例（调度器/时间/日志/校验器/HTTP 客户端/DB/DataStore/各 Repository/RuleEngine/ParserPipeline/领域服务）；ViewModel 通过 `companion fun factory(container, args…)` 创建。装配层组合 parser+data 实现 `ImportService`/`ReadingService`，使 presentation 只依赖 domain。
- **日志**：`AppLogger` 统一（debug 构建输出 Logcat，release 仅 WARN+）；日志**禁止**输出用户粘贴的完整 URL 查询串与正文内容（隐私最小化），一律截断+脱敏。
- **时间**：所有时间戳取自注入的 `TimeProvider`，测试可替换。
- **ID**：数据库主键自增；规则 ID 命名 `<domain-slug>.<semver-slug>` 或 `manual.<domain>`。
- **性能预算**：冷启动到书架 ≤ 1.5s（无网络请求阻塞）；万章级目录列表用投影+分页加载（每页 200 条）；长正文分页计算在 Default 线程且结果按章缓存（layoutVersion 失效）；正文大字段（约 30k 字/章）一期存 DB TEXT 列，批量全本缓存若引出 GB 级库体积，二期迁移文件存储（03 文档 §9 已预留策略）。
