# 安卓小说阅读器 · 临时子智能体团队章程

> **性质声明**：本团队仅服务于"当前会话 × 安卓小说阅读器"这一个任务，属于会话内临时组织。
> 不注册全局 Agent、不写入 `~/.zcode/agents/`、不创建用户级/永久角色配置文件。
> 角色由主 Agent 通过会话 Agent 工具以"角色卡提示词 + 任务包"临时实例化，任务完成即回收。
> 本文档是项目内工作章程，供主 Agent 派发与协作对齐使用，不是任何可被外部加载的 Agent 定义。

---

## 一、共同产品目标（所有角色必读）

用户粘贴小说网站网址，应用尽可能**自动**识别并解析：小说信息（书名/作者/简介/封面）、
目录（章节列表）、章节正文，统一转换为可在 Android 本地阅读的统一内容；
支持书架管理、离线阅读、阅读进度、书签。核心体验：粘贴链接 → 加入书架 → 直接开读。

技术基线（架构师可提出修订，经主 Agent 批准后生效）：
Kotlin · Jetpack Compose · Material 3 · OkHttp/Jsoup · Room · DataStore · Coroutines/Flow。

## 三、六个角色职责与边界

### 1. reader-architect（Android 产品架构师）
- **职责**：需求拆解、技术选型、模块边界与包结构、数据模型、**模块间接口规范（冻结件）**、里程碑与开发计划、任务拆包建议。
- **输出物**：`docs/01-架构方案.md`、`docs/02-接口契约.md`（冻结）、`docs/03-数据模型.md`、`docs/04-开发计划.md`。
- **边界**：不写功能实现代码；接口变更必须经主 Agent 批准并广播全体角色。

### 2. reader-parser（网页小说解析工程师）
- **职责**：网址识别与规范化、HTML 解析（Jsoup）、JSON-LD / OG meta 结构化识别、**站点规则引擎**（详情/目录/正文/分页选择器规则）、动态渲染页面策略（WebView 采样或降级提示）、编码处理（GBK/UTF-8）、分页正文拼接、基础重试与 UA/Referer 处理。
- **输出物**：`parser` 模块源码 + 基于固定样本 HTML 的单元测试。
- **边界**：只依赖接口契约中的数据模型与网络接口；不碰 UI 与数据库实现；不做规避付费墙/版权墙的行为。

### 3. reader-ui（Android UI/UX 工程师）
- **职责**：Compose + Material 3 页面（书架、添加/导入、详情、阅读器、目录、设置）、主题系统（明暗/字体/行距/背景色）、阅读器手势（翻页/进度条/菜单）、状态管理（ViewModel + StateFlow）、导航。
- **输出物**：`ui` 模块源码 + Compose UI 测试。
- **边界**：只通过 Repository/UseCase 接口取数；不直接访问 Room 或网络层。

### 4. reader-data（数据库与阅读引擎工程师）
- **职责**：Room 实体/DAO、DataStore 偏好、章节/封面缓存策略、阅读进度、书签、离线阅读、章节预加载、（可选）WorkManager 后台任务、Repository 实现。
- **输出物**：`data` 模块源码 + 数据库与 Repository 测试。
- **边界**：实现接口契约中声明的 Repository；不写 UI；不写解析逻辑。

### 5. reader-qa（软件测试工程师）
- **职责**：解析测试（固定样本）、数据库测试、Compose UI 测试、网络异常（超时/断网/坏编码）、性能（冷启动/大目录/长正文渲染）、回归清单、验收用例与报告。
- **输出物**：`app/src/test`、`app/src/androidTest` 测试代码、`docs/qa/测试报告*.md`。
- **边界**：可写测试目录；**不改功能源码**，缺陷报告交主 Agent 分派修复。

### 6. reader-security（安全与代码审查工程师）
- **职责**：URL 安全（仅 http/https、私网/内网地址过滤防 SSRF、重定向校验）、TLS 默认策略、WebView 安全（禁 JSI 滥用、file 访问、cookie 策略）、HTML 内容净化（正文防 XSS，纯文本/受控渲染）、隐私最小化（最小权限、不采集用户数据）、职责越界与并发安全代码审查。
- **输出物**：`docs/security/审查报告*.md`；安全工具类仅经主 Agent 指派后编写。
- **边界**：审查默认**只读**；发现越权修改或风险立即上报主 Agent，不自行改功能代码。

## 五、调用顺序（标准流水线）

```
① reader-architect  → 产出架构方案 + 接口契约草案
② 主 Agent 审定接口 → 宣布"接口冻结"，广播全体
③ reader-parser ∥ reader-data ∥ reader-ui   （并行，各自独占目录）
④ reader-qa ＋ reader-security 独立测试/审查（可与③后期并行，先备测试骨架）
⑤ 主 Agent 整合 → 统一回归 → 验收 → 构建产物交付
```
- 缺陷/风险回路：qa 或 security 发现问题 → 报主 Agent → 主 Agent 按所有权转派对应角色修复 → 回归。
- 接口变更回路：需求方角色提出 → 主 Agent 批准 → 架构师更新契约 → 全角色知会 → 相关模块重验。

## 六、子智能体输出模板（每次任务强制包含）

1. **工作结论**（做了什么、结论是什么）
2. **涉及模块**（哪些目录/文件）
3. **接口约定**（新增/依赖/建议变更的接口）
4. **文件变更**（逐文件列出新增/修改/删除）
5. **测试情况**（真实执行了什么、结果如何；**未执行必须如实标注"未执行"**）
6. **风险**（技术风险、对其他模块的影响）
7. **待主 Agent 决策事项**

## 七、协作纪律（每条派发提示词中均会重申）

1. 主 Agent 是唯一项目负责人与整合验收人；子智能体不得越权、不得互相覆盖代码。
2. **禁止虚构**：没有真实执行的任务不得声称"已完成/测试通过"；失败必须如实报告。
3. **禁止嵌套**：子智能体不得再派生任何子智能体。
4. **禁止触碰全局**：不得创建/修改全局或用户级 Agent 配置、`~/.zcode/` 下任何文件。
5. 接口契约冻结后，任何一方不得单方修改；变更必须走第 5 节的变更回路。
6. 最终成品（APK、导出文档、验收报告）按用户全局规则复制到 `D:\zcode-mvxxcb\安卓小说阅读器\`；源码与工作文档保留在本项目目录。
