## K8 BookResolver（domain/service/BookResolver.kt，模型入 domain/model/ResolverModels.kt）

```kotlin
/** 反向识别结果：任意章节/详情/目录 URL → 整本书定位（多路证据，带置信度） */
data class BookResolution(
    val normalizedUrl: String,
    val kind: PageKind,                     // 输入页型判定
    val detailUrl: String?,                 // 定位到的详情页（可空，禁止 URL 猜测合成）
    val catalogUrl: String?,                // 定位到的目录页
    val detail: ParsedBookDetail?,          // 经 pipeline.parseDetail 的输出
    val catalog: ParsedCatalog?,            // 经 pipeline.parseCatalog 的输出
    val chapters: List<ChapterRef>,         // = catalog.chapters（便捷冗余）
    val confidence: Confidence,             // 各路证据置信度取 min
    val requiresCatalogHint: Boolean,       // true=找不到目录，UI 必须提示用户补充目录页 URL
    val evidence: List<String>,             // 判定依据（面包屑/meta/JSON-LD/OG/规则/上一章链，供 UI 展示）
)

interface BookResolver {
    /** 六种输入统一入口：详情页/目录页/首章/中间章/末章/复杂参数章节页 */
    suspend fun resolve(rawUrl: String, catalogHint: String? = null): AppResult<BookResolution>
}
```

实现：`service/DefaultBookResolver.kt`（装配层）。策略（**静态路径，无 WebView**）：
1. `UrlClassifier.classify` → BOOK_DETAIL：parseDetail→catalogUrl；CATALOG：直接 parseCatalog；
2. CHAPTER：**面包屑提取**（parser/util/BreadcrumbLinkExtractor，新增）产出候选详情/目录链接（≤6 个，逐个 classify 验证）→ 命中即解析；
3. 候选未命中 → **上一章回溯**：沿 ParsedChapterContent.previousChapterUrl 有界回溯（≤30 跳、请求预算 ≤ ParseOptions.maxTotalRequests），沿途每页重试面包屑，命中即止；
4. catalogHint 非空时优先按提示 URL 解析目录（用户补充回路）；
5. 全部失败 → 返回 Success(requiresCatalogHint=true, 已有 partial 字段如实填充) 或 Failure(Parse.CATALOG_UNRESOLVED)。**禁止**：从 URL 字符串推测书名/目录地址；无边界枚举同域链接。
集成点：ImportViewModel（章节 URL 导入升级为整本识别，临时书语义保留兜底）；CrawlCrawler 入口复用。

## K9 CrawlTask 模型与状态机（domain/model/CrawlModels.kt）

```kotlin
enum class CrawlState { WAITING, RUNNING, PAUSED, FAILED, COMPLETED, CANCELLED }

data class CrawlTask(
    val id: Long, val bookId: Long, val state: CrawlState,
    val totalChapters: Int,                 // 规范化后目录总章数
    val succeededCount: Int, val failedCount: Int,

```

状态机（非法转移 → `State(INVALID_TASK_STATE)`，校验在 CrawlTaskRepository 单点执行）：
`WAITING→RUNNING→{COMPLETED|FAILED|CANCELLED|PAUSED}`；`PAUSED→RUNNING`（继续）；`FAILED→WAITING`（重试失败=未缓存章重入队）；`WAITING/RUNNING→CANCELLED`；终态再入队=新建任务。约束：同一时刻同书至多一个非终态任务（Repository 强制）。章节级状态以 `chapters.isCached` 为 DB 真值派生（失败清单=未缓存且非 isMissing，天然支持"已下载章不重采"）。

## 5.2 加载状态机与窗口策略

- 状态机：`INIT → WINDOW_LOADING → READY → (APPEND_NEXT | PREPEND_PREV | TRIM_FAR) → READY`；槽级：`Pending→Loading→Ready|Failed`；Failed 可 retry→Loading。
- 初始窗口 = 当前章 ±1；**临近章尾自动加载下一章**：可见项进入末章倒数 3 屏或 ChapterDivider 可见 → 追加；向前同理（回滚上限回溯 ≤1 章）。
- **内存上限**：窗口内最多 5 章 Ready（LRU 裁剪最远章→Pending；items 重建）；**不整本进内存**。
- **不重复请求**：同一 chapterIndex 的 Loading 槽复用同一 Job；Ready 槽不重载；失败指数退避（同章 3 次失败转手动重试）。
- **预加载与缓存**：追加前经 `cacheManager.prefetchNeighborhood(bookId, nextIndex, radius=1)` 预写缓存（复用现有，静默失败）；断网时 Ready 槽读缓存、未缓存槽呈 Failed(OFFLINE)+cachedAvailable 提示（对齐 §10 OFFLINE 行）。
- **不并发轰炸**：全局单加载 Job 串行（同书串行原则）；域名间隔由 SecureHttpClient 兜底。

## 5.3 ReaderViewModel 改造方案（保留双模式路由）

- `readingMode == CONTINUOUS` → 连续分支：构建 ContinuousReadingState（ContinuousReaderController 持有），ReaderScreen 渲染 ReaderContinuousHost；`SCROLL/PAGE_SIMULATED` 分支与 pendingRestoreFraction/viewport/分页链路**零改动**。
- 既有入口保留：goToPreviousChapter/goToNextChapter/jumpToChapter 在连续模式下等价于"跳转到该章 Divider 锚点"；手动上下章入口（工具栏）继续可用。
- 进度保存：连续模式 charOffset 主锚点（见 5.4），防抖 500ms/ON_STOP 强制保存链路复用。

## 5.4 进度模型（charOffset 主锚点 + fraction 兜底）

| 字段 | 语义 |
|---|---|
| chapterId/chapterIndex | 章节定位（既有） |
| `charOffset`（v2 新列） | **主锚点**：当前首可见段落块在本章内的累计字符偏移（由 blocks 逐块累计求得；写入与恢复同口径） |
| inChapterFraction | 兜底：charOffset/全章字符数（旧数据 -1 时按现有 fraction 链路恢复） |
| scrollOffsetPx | 瞬态（不持久化） |

恢复矩阵（全部场景走同一链路：退出/回书架/切书/系统回收/换主题/改字号行距/目录更新）：charOffset≥0 → 载入该章 → 二分找首个累计字符 > charOffset 的块为起始项 → scrollToItem；charOffset=-1（旧数据）→ fraction 路径（现状不变，用户翻页后自愈写新锚点）；内容重抓导致越界 → 钳制章尾并在保存时校正（06 K6 语义一致）。reader 路由 ?charOffset= 支持书签/跨章跳转直达（06 K3）。
